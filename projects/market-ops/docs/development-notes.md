# 实现记录与下一步

这个练习从金融投资运营岗位的三项日常工作出发：整理市场与系统信息、清洗市场数据及反馈、完成 IT 支持。范围控制在本地文件输入和可复现报告，不模拟一套交易终端。

开发使用 ChatGPT / Codex 辅助设计、实现和测试。程序运行时不调用大模型，报价与优先级由明确规则计算。公开资料整理依据官方页面，未使用模型生成的传闻或无来源竞品结论。

## 做过的核对

- 百分比与小数混用会造成 100 倍差错，所以原单位与标准单位分别保存。
- 发布时间与接收时间同时参与截止判断；“当天发布”并不等于“当时已收到”。
- 时区先转换到截止时区再比较业务日期，避免把零点附近的 UTC 时间误判为前一日。
- 修订冲突不能按 CSV 文件顺序选择，加入整组隔离和输入重排测试。
- 需求分数取实际单条记录的最大值，避免跨记录拼接后虚增优先级。
- 债券样例分别选择票息日和非票息日，使应计利息与净价 / 全价差可以直接观察。

21 项测试覆盖时点、单位、修订、缺失、反馈合并、债券口径和重复运行一致性；GitHub Actions 同时跑 Python 3.10 / 3.12。测试证据只支持当前小范围流程。

## 尚需补充

接入真实数据前，需要逐一确认标的映射、交易日历、授权条款、资产成交量单位、公司行动与合约换月、债券特殊条款及结算约定。原始输入由外部系统提供可信接收时间；本项目无法证明该时间没有被回填。

需求台账只做排序和导出，不连接工单平台，不替团队指派负责人。行业资料是人工维护的静态清单，需定期复核原始页面。下一步最有价值的改进是接一份授权行情导出，用真实异常验证字段与处理口径。
