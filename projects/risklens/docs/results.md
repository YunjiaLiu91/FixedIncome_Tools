# 样例观察

固定种子 42，估值日 2026-09-28。六类资产、756 个工作日、五笔虚构订单。完整计算保存在 `examples/demo/summary.json`。

| 指标 | 结果 |
|---|---:|
| NAV | 10,000,000 CNY |
| 最近 252 日一日 VaR，97.5% | 176,318 CNY，1.76% NAV |
| 同口径 ES | 225,368 CNY，2.25% NAV |
| 近 252 日年化波动 | 12.50% |
| 固定当前权重重建路径最大回撤 | −22.67% |
| 滚动回测 | 504 日，12 次突破，2.38% |
| Kupiec 覆盖率检验 p 值 | 0.8630 |
| 检查结果 | 51 项检查，10 项未通过 |
| 订单结果 | 3 笔 BLOCK，2 笔 PASS_DEMO_CHECKS |

VaR 预算通过不代表组合没有问题：SIM_TECH_A 占 NAV 的 36%，超过单资产上限 30%；科技行业合计 56%，超过行业上限 45%；SIM_TECH_A 在 10% ADV 参与率下预计退出需要 6 日，超过 5 日设定。

## 订单反例

| 订单 | 情况 | 结果 |
|---|---|---|
| ORD-001 | 买入限制名单资产 | O01 未通过 |
| ORD-002 | 过期 KYC、客户等级低于产品、较大买入订单 | O02 / O03 / O04 / O05 / O06 未通过 |
| ORD-003 | 小额卖出 SIM_BANK | 演示订单规则通过 |
| ORD-004 | 小额买入 SIM_GOLD | 演示订单规则通过 |
| ORD-005 | 卖出金额超过现有黄金持仓 | O05 未通过 |

这些是预设反例和对照样例，不是现实异常识别率评估，不能写成“识别准确率 100%”。多条规则可以命中同一订单，因此未通过检查数与被拦订单数不同。

## 压力试算

| 场景 | 组合损益 | NAV 变化 |
|---|---:|---:|
| 股票 −20%、利率 +100bp、黄金 +5% | −1,446,000 CNY | −14.46% |
| 股票 −5%、利率 +200bp、黄金 −3% | −533,000 CNY | −5.33% |
| 股票 −30%、利率 +150bp、黄金 −10% | −2,291,500 CNY | −22.91% |

当前股票持仓合计 70%，压力损益主要由股票暴露决定。黄金的历史波动贡献略为负，说明在这个模拟窗口内提供部分对冲，不能外推为稳定的避险性质。

较高的 Kupiec p 值只表示这个样本未显著拒绝无条件覆盖率假设，不意味着模型可靠。后续需要独立性检验、不同市场阶段、真实数据和固定验证集。

## 验证与下一步

本地已通过 23 项测试，覆盖尾部质量、首次损失回撤、未来信息排除、风险贡献加总、手算压力损益、订单边界、无效输入、AI 数值引用和 CSV 复现。CI 同时配置 Python 3.10 和 3.12。

下一步优先实现订单累计额度和冻结资金，再接入真实持仓与行情做小样本核对。已有持仓超限的处置与业务人员复核流程需要独立设计，不能由模型自由文本替代。
